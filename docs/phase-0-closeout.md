## Findings and decisions

- **Documented compatibility:** The public source and registry evidence supports stock PG16.16 Bookworm as a pinned source candidate and identifies the DuckPipe PG18 CI artifact for the first remote test. The inspected writer dependency expects DuckLake 0.4, while the serving candidate targets 1.0. This is source/build evidence. Check the real catalog before any downstream attachment or migration. [Compatibility matrix](compatibility-matrix.md)
- **Approved design:** The accepted research topology separates source and consumer PostgreSQL, DuckLake metadata from object storage and compute, and Windmill job state from catalog and request state. Two object buckets have distinct contracts. The merged runtime plan describes how to test these boundaries on one disposable host. [Architecture](architecture.md) · [Local runtime design](local-runtime-design.md)
- **Observed behavior:** GitHub and the local checkout confirm PRs #13–#17 are merged, issues #6–#10 are closed and Done, and Phase 0 is the sole milestone with #11 open. The hosted and local developer checks exercised repository tooling. The fixture arithmetic and document contracts were checked statically. Phase 0 exercised no PostgreSQL, DuckPipe, lake, S3, Windmill or application runtime. No full research-question acceptance condition changed.
- **Untested hypotheses:** The source will reproduce exact states and safe resets, overlap and replay under real PostgreSQL. Remote snapshot/change parity, slot/ack and resource behavior during catch-up, shared-catalog reads and writes, downstream atomicity and request durability all require runtime evidence. The pinned DuckPipe image's trust rules and the catalog-format gap are later experiment constraints. [Research register](research-questions.md)
